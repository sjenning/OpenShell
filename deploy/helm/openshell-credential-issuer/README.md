This experimental chart deploys only `openshell-credential-issuer`, independently
of the gateway and its database. It exposes one private ClusterIP port (8443),
with mandatory private-CA mutual TLS and exact SPIFFE gateway/workspace bindings.
It does not create a gateway listener, public ingress, database, certificates,
KEK, or credential-bearing Kubernetes Secret.

## Provision and install

Prepare a protected `issuer.toml` using `examples/issuer.toml` as a shape example.
Replace the SQL URL with a dedicated database and credentials, and configure the
exact authorized gateway SPIFFE URI identities and workspace lists. Do not use
wildcards or a gateway user/operator certificate. The issuer server certificate
needs a DNS SAN matching its Service endpoint. Only gateway client certificates
signed by `client-ca.pem` and authorized by the issuer configuration can resolve
values. NetworkPolicy selectors do not replace that authorization.

Provision the following existing Secrets in the release namespace, using your
secret manager or protected local files (never `--set` or inline chart values):

- `issuer-config`: complete configuration under `issuer.toml`, including SQL credentials.
- `issuer-tls`: `tls.crt`, `tls.key`, and `client-ca.pem`.
- `issuer-kek`: a shared, independently backed-up 32-byte encryption key under `key`.

For example, with existing protected local files:

```shell
kubectl -n security create secret generic issuer-config --from-file=issuer.toml=/secure/issuer.toml
kubectl -n security create secret generic issuer-tls \
  --from-file=tls.crt=/secure/tls.crt --from-file=tls.key=/secure/tls.key \
  --from-file=client-ca.pem=/secure/client-ca.pem
kubectl -n security create secret generic issuer-kek --from-file=key=/secure/encryption.key
helm install credential-issuer ./deploy/helm/openshell-credential-issuer \
  --namespace security --values /secure/issuer-values.yaml
```

`issuer-values.yaml` contains references and network selectors only:

```yaml
config:
  existingSecret: issuer-config
tls:
  existingSecret: issuer-tls
encryption:
  existingSecret: issuer-kek
networkPolicy:
  ingressFrom:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: gateways
      podSelector:
        matchLabels:
          app.kubernetes.io/name: openshell
```

NetworkPolicy denies all ingress until you supply peers. For gateways in another
cluster, arrange private routing to the ClusterIP endpoint and permit only the
routed source CIDRs; this chart does not provision cross-cluster networking or
TLS-terminating ingress. Egress is operator-managed: permit DNS, SQL, configured
storage backends, minters, and upstream token endpoints as required.

## Configuration and storage

The complete TOML is mounted from a Secret, not serialized through values or a
ConfigMap. All replicas mount the same configuration, server identity, KEK source,
and registration Secrets read-only with group-restricted permissions. A non-root
init container copies the shared KEK into a UID-owned, memory-backed `0600` file:
the encrypted-store loader restricts its permissions and cannot use a root-owned,
read-only projected Secret directly. Only this runtime copy is writable. Paths are:

- Config: `/etc/openshell-issuer/config/issuer.toml`.
- TLS: `/etc/openshell-issuer/tls/{tls.crt,tls.key,client-ca.pem}`.
- KEK: `/etc/openshell-issuer/encryption/key`.
- Optional registration Secrets: `/etc/openshell-issuer/registrations/<name>/<key>`.
- Optional existing data PVC: `/var/lib/openshell-issuer`.

Set TOML `listen = "0.0.0.0:8443"` and keep its `replicas` equal to
`replicaCount`. Scale by updating both the Secret and Helm values. The chart
rejects replicas above one unless `database.kind=postgresql`; the binary also
rejects a multi-replica SQLite URL. Since Helm does not read Secret contents,
operators must keep these declarations aligned. A startup init container runs
`--check-config`, and the daemon revalidates before initializing backends.

SQLite requires `database.kind=sqlite`, `replicaCount=1`, an existing PVC, and a
URL such as `sqlite:///var/lib/openshell-issuer/issuer.db?mode=rwc`. SQLite uses
`Recreate` rather than rolling updates to avoid overlapping runtime instances.
PostgreSQL uses rolling updates and does not need a local PVC. Back up the SQL
database and KEK separately; losing the key makes recovery state unreadable.

Register remote minters and first-party Vault/Kubernetes storage in the TOML
using the [credential issuer reference](https://docs.nvidia.com/openshell/latest/extensibility/credential-issuer).
Add each minter CA/client identity or backend token Secret to
`registrationSecrets`; no secret contents go into values. Each `name` must be a
lowercase DNS label of at most 50 characters so the `registration-` volume name
fits Kubernetes' 63-character limit. This limit does not shorten `secretName`.
The chart defaults to no API token or RBAC. If Kubernetes Secrets storage or Vault
Kubernetes auth requires a token, enable
`serviceAccount.automountServiceAccountToken` and grant only the backend-specific
permissions to the dedicated ServiceAccount outside this chart. It has no
permission to read gateway Secrets.

## Upgrade and diagnose

Config and backend-registration changes require a restart. Change
`config.revision` to a non-secret revision label after updating those Secrets.
Do not put a secret or its contents in that label. TLS files use whole-directory
Secret mounts (not `subPath`) so projected certificate updates reach the daemon;
it reloads them on new connections. Give certificate chains time to project and
replace matching cert/key files together. KEK rotation is not a restart-only
operation; follow a supported re-encryption procedure, never simply replace it.

The Pod runs as UID/GID 1000 without added capabilities or privilege escalation,
with a read-only root filesystem. Startup/readiness TCP probes check the private
listener only; they are not authenticated application health checks. No liveness
probe kills admitted mint operations during backend outages. Keep
`terminationGracePeriodSeconds` greater than TOML `shutdown_timeout_seconds`
(defaults 210 and 180 seconds).

Inspect Deployment/init-container status, Secret key names (not values), mounted
file access, and issuer logs. Do not print issuer TOML or include it in support
bundles. Never disable TLS or open the gateway's public listener as a repair.

## Build and verify locally

```shell
mise run docker:build:credential-issuer
mise run docker:smoke:credential-issuer
mise run helm:test:credential-issuer
```

For the deployment E2E lane, `mise run e2e:credential-issuer:images` serially
builds matching native gateway, issuer, sandbox, supervisor, and custom-minter
fixture images without publishing. The default fixture image is
`openshell/credential-issuer-e2e-fixture:dev`; set
`OPENSHELL_ISSUER_E2E_FIXTURE_IMAGE` to override it. The separate-cluster test
fixture owns cluster creation, image loading, private routing, and teardown.

The smoke task runs the built image's version and config checks without network
access. For a non-Helm container, provision its KEK as a UID-1000-owned `0600` file
on a writable dedicated mount; keep the source Secret and all other identity files
read-only. The runtime must be able to restrict KEK permissions. `helm:test:credential-issuer` builds the binary only when no
`ISSUER_BIN` override is supplied; set that override to reuse a serialized build.
Existing release lanes build native amd64/arm64 issuer binaries, smoke the exact
candidate OCI archive on each architecture, and publish the issuer image and
chart alongside gateway artifacts after their existing release dependencies.
The image is `ghcr.io/nvidia/openshell/credential-issuer`; the chart is
`oci://ghcr.io/nvidia/openshell/openshell-credential-issuer`. Dev releases publish
`0.0.0-dev` and SHA-pinned chart versions; public chart versions are immutable.
Do not assume a version is published until its release jobs have succeeded.
