The experimental `openshell-credential-issuer` service hosts private credential
storage and refresh RPCs. It owns its database, encrypted mint-result recovery,
storage registrations, and refresh scheduling. It does not serve gateway APIs.

The gateway hosts the same issuer store, refresh, authorization, watch, and cache
handlers in process by default. Select standalone hosting explicitly through the
[credential issuer configuration](/how-it-works/gateways/configuration#remote-credential-issuer).
Both modes manage provider values, refresh grants, sandbox SSH host private keys,
and stored supervisor launch material. Internal secrets use typed sandbox or
supervisor-instance owners rather than synthetic providers. Gateway TLS identity
and launch-signing key files remain separate bootstrap configuration.

Registered custom strategies support profile-driven multi-output grants as well
as single outputs. Configuration, rotation, deletion, and metadata-only replay
use the same gateway publication path in either mode. Issuer revocation or
unknown watch metadata invalidates installed static credentials through polling,
connected push sessions, and push-session reconnection. Reconciliation does not
reinstall pre-outage cached values.

Embedded startup performs a restartable upgrade of legacy inline values, driver
handles, internal-secret handles, and refresh grants. Existing reference versions,
revocation, cleanup ownership, and grant authorization epochs remain intact.
The upgrade preserves existing refresh lead times and positive lifetime limits,
including limits above the twelve-hour maximum for new grants. Classified
retryable failures retain their retry deadlines; uncertain mint attempts remain
parked. Moving from embedded to standalone hosting is different: the gateway
does not copy legacy values or load a local value driver or credential KEK in
remote mode. Arrange that migration explicitly before changing source selection.
Starting this service alone changes neither the gateway's source selection nor
its existing storage.

## Package and deploy

The standalone issuer has a separate OCI image and Helm chart; deploying it does
not expose a gateway listener. Build and smoke-test a local image from a source
checkout:

```shell
mise run docker:build:credential-issuer
mise run docker:smoke:credential-issuer
```

The image runs as UID/GID 1000, listens only on the configured private mTLS
endpoint, and defaults to `--config /etc/openshell-issuer/issuer.toml`. Mount the
complete configuration and TLS files read-only; keep SQL credentials out of image
layers and command-line arguments. The encrypted-store loader restricts KEK file
permissions, so give UID 1000 a dedicated writable, owner-only KEK file rather
than a root-owned projected Secret. It uses the same pinned Distroless Debian
runtime as the gateway.

Install the separate `deploy/helm/openshell-credential-issuer` chart with existing
Secrets for the complete `issuer.toml` (including SQL credentials), server
certificate/key and explicit client CA, and a provisioned shared 32-byte KEK.
Chart values contain Secret names, not secret contents:

```shell
helm install credential-issuer ./deploy/helm/openshell-credential-issuer \
  --namespace security \
  --set config.existingSecret=issuer-config \
  --set tls.existingSecret=issuer-tls \
  --set encryption.existingSecret=issuer-kek \
  --values /secure/issuer-network-values.yaml
```

The chart mounts TOML at `/etc/openshell-issuer/config/issuer.toml`, TLS files under
`/etc/openshell-issuer/tls`, the KEK at `/etc/openshell-issuer/encryption/key`, and
optional minter/backend Secrets below
`/etc/openshell-issuer/registrations/<name>`. A non-root init container copies the
read-only KEK Secret into a UID-owned `0600` memory-backed file for the runtime;
it never generates replacement keys. Register storage and minters in the
Secret-backed TOML using those paths. It grants no backend RBAC and disables API
token mounting by default; explicitly grant only what the selected backend needs.

The only Service is ClusterIP port 8443. NetworkPolicy denies all ingress until
`networkPolicy.ingressFrom` permits the gateway peers. Arrange private routing
for cross-cluster clients; the chart does not create public ingress or terminate
TLS. Configure exact gateway SPIFFE identities and explicit workspace lists in
TOML. Keep `listen = "0.0.0.0:8443"`, TOML `replicas`, and chart `replicaCount`
aligned. More than one replica requires PostgreSQL; single-replica SQLite also
requires an existing data PVC and uses `Recreate` upgrades.

Set `config.revision` to a new non-secret label when restarting after config or
registration changes. Keep the Pod termination grace longer than the configured
shutdown deadline. See the chart README for Secret key names, configuration
examples, and rollout checks. The existing release lanes publish
`ghcr.io/nvidia/openshell/credential-issuer` and
`oci://ghcr.io/nvidia/openshell/openshell-credential-issuer` alongside gateway
artifacts. Candidate archives undergo native amd64/arm64 image smoke checks.
Use only tags whose release jobs succeeded; source builds do not imply a
published registry tag.

## Configure the service

Create a dedicated database and restrict access to the issuer. Use PostgreSQL
for more than one replica; SQLite supports a single runtime. The SQLite example
uses `mode=rwc` to create the database file. Create the data directory before
starting the service.

```toml
[openshell.credential_issuer]
listen = "0.0.0.0:8443"
# Optional plaintext monitoring listener; keep it private.
metrics_bind_address = "127.0.0.1:9091"
database_url = "sqlite:///var/lib/openshell-issuer/issuer.db?mode=rwc"
replicas = 1
key_encryption_key_path = "/var/lib/openshell-issuer/encryption.key"
tls_cert_path = "/etc/openshell-issuer/tls.crt"
tls_key_path = "/etc/openshell-issuer/tls.key"
tls_client_ca_path = "/etc/openshell-issuer/client-ca.pem"
cache_ttl_seconds = 60
refresh_interval_seconds = 10
shutdown_timeout_seconds = 180

[openshell.credential_issuer.gateway_identities]
"spiffe://example.org/gateway/production" = ["default"]
```

All cryptographic file paths must be absolute. The server certificate needs a
DNS SAN matching the client's HTTPS endpoint. Every caller must present a
certificate signed by the explicit client CA with exactly one canonical SPIFFE
URI SAN. Map each allowed gateway identity to explicit workspace names; wildcard
identities and workspaces are not accepted. Headers and bearer tokens do not
establish issuer identity.

Provision the same 32-byte encryption key for all replicas. A single-replica
issuer can create a missing key file using the encrypted database driver's
protected-file behavior. Back up the key separately from the database. Losing
it makes stored values and mint-result spools unrecoverable. Set `replicas` to
the deployed count; replicated deployments require PostgreSQL and a key file
that exists before startup.

The default storage registration is `openshell-driver-db-credstore`. To use
Vault or Kubernetes Secrets, set `storage_driver` to `vault` or
`kubernetes-secrets` and configure the corresponding
`[openshell.credential_drivers.<name>]` table with its existing driver options.
The shared encryption key still protects issuer-owned recovery state. The
standalone host currently accepts these first-party registrations, not external
driver subprocesses or arbitrary registration aliases.

## Audit and metrics

The standalone process writes secret-safe OCSF audit records to stdout separately
from operational JSON logs. The OCSF stream is independent of the operational
`RUST_LOG` filter. Audit records cover authentication and authorization denials,
mutating operations, committed reference mutations, and durable grant state
transitions. They can identify the authenticated gateway, workspace, and logical
reference or grant; they omit values, physical driver handles, request
fingerprints, and upstream error bodies. These observations do not replace
durable grant receipts or prove exactly-once upstream execution.

Resolution requires an explicit purpose: sandbox delivery, operator export,
refresh, or metadata inspection. Authorized resolution logs record the gateway,
purpose, and batch count without values. Metadata inspection reads versions and
expiration without fetching backend values. Purpose is part of the value-cache
binding, not an alternative to immutable-owner authorization.

Omit `metrics_bind_address` to disable the standalone Prometheus listener. When
configured, it serves `/metrics` over a separate plaintext HTTP listener with no
TLS or caller authentication. Use loopback or an isolated monitoring network and
restrict network access. The address must have a nonzero port and differ from
`listen`; a bind failure prevents startup. The issuer chart does not expose this
optional listener automatically.

Metrics use only bounded operation, outcome, gRPC-code, and grant-phase labels,
never provider names, references, workspace IDs, hashes, or endpoint URLs:

| Metric | Observation |
|---|---|
| `openshell_issuer_operations_total` | Completed or cancelled operations by operation and outcome. |
| `openshell_issuer_operation_failures_total` | Failures by operation and gRPC code. |
| `openshell_issuer_access_denied_total` | Authentication and authorization denials. |
| `openshell_issuer_operations_in_flight`, `openshell_issuer_operation_duration_seconds` | Current operation count and elapsed operation time. |
| `openshell_issuer_grant_transitions_total` | Committed changes by resulting grant phase. |
| `openshell_issuer_cleanup_deferred_total` | Backend cleanup failures retained for later retry. |
| `openshell_issuer_grants`, `openshell_issuer_scheduler_last_success_timestamp_seconds` | Phase counts and timestamp from the last complete successful scheduler sweep. |

Embedded handlers emit the same instrumentation through the gateway's existing
metrics recorder and OCSF subscriber; they do not open another listener.

## Start and stop

Check syntax and semantics without opening databases, contacting minters, or
reading cryptographic files:

```shell
./target/release/openshell-credential-issuer --config /etc/openshell-issuer/issuer.toml --check-config
```

Start the service:

```shell
./target/release/openshell-credential-issuer --config /etc/openshell-issuer/issuer.toml
```

Startup validates TLS material and initializes storage and pinned minters before
listening. Every new connection reloads the server certificate, key, and client
CA files. Publish matching files together. Missing, inconsistent, or malformed
replacements reject new handshakes; they never reuse the previous identity.
Existing authenticated connections retain their negotiated identity.

On SIGTERM or Ctrl-C, the service stops scheduling and accepting mutations,
closes watches, and waits for admitted work and transport shutdown. Give the
process manager at least `shutdown_timeout_seconds` to drain. A forced exit or
elapsed deadline does not authorize repeating an uncertain upstream exchange.

## Register a remote minter

The issuer includes the built-in OAuth, Google service-account, and AWS STS
strategies. Add a stateless remote minter with a matching `custom:<name>`
descriptor:

```toml
[openshell.credential_issuer.minters.company-sts]
endpoint = "https://minter.security.example.org:8443"
tls_ca_cert_path = "/etc/openshell-issuer/minter-ca.pem"
tls_client_cert_path = "/etc/openshell-issuer/issuer-client.crt"
tls_client_key_path = "/etc/openshell-issuer/issuer-client.key"
```

For embedded hosting, put the same fields under
`[openshell.gateway.credential_minters.company-sts]` in the gateway configuration.
Do not configure gateway minters when selecting a remote issuer. See
[embedded minter registration](/how-it-works/gateways/configuration#register-embedded-custom-minters).

This registration requires the descriptor `custom:company-sts`. Discovery failure
or a mismatched descriptor fails startup. The minter must authorize the issuer's
verified client identity separately from gateway identities. It receives only
strategy configuration, secret material, and an attempt ID, not gateway profiles
or storage handles. Mutations never retry an unknown upstream outcome blindly.

Instead of the PEM client pair, select one exact local SPIFFE Workload API
identity:

```toml
workload_api_endpoint = "unix:///run/spire/sockets/agent.sock"
spiffe_id = "spiffe://example.org/issuer/production"
```

Do not combine both identity modes. Both require explicit private server trust
and independent HTTPS hostname verification. Client identities reload on each
new connection. The configuration file can contain database or backend secrets;
restrict its permissions and do not include it in support bundles.

## Configure a custom refresh

Configure a registered minter through `ConfigureProviderRefresh` in either
hosting mode. Set `strategy_name` to its exact registered name, leave the legacy
`strategy` enum unspecified, and select the primary output environment key with
`credential_key`. A matching custom profile can supply `strategy_name` when both
request selectors are omitted.
Send the descriptor's configuration and secret fields together in `material`.
The gateway separates them using the issuer descriptor, even when you omit
`secret_material_keys`. If you supply that list, every entry must identify
present secret material, not a configuration field. For example, a minter with
configuration field `audience`, secret field `seed`, and output `company_token`
accepts this request body through the SDK's `ConfigureProviderRefresh` RPC.

```json
{
  "workspace_scope": { "workspace": "default" },
  "provider": "company",
  "credential_key": "COMPANY_TOKEN",
  "strategy_name": "custom:company-sts",
  "material": { "audience": "company-api", "seed": "<refresh-material>" },
  "request_id": "<stable-UUID>"
}
```

The provider must already exist. A profile refresh declaration must name the
same custom strategy. Profile import, update, and lint validate custom and
built-in minters against the selected issuer catalog; a custom-name prefix alone
never establishes availability. Profile material classifications must agree
with the issuer descriptor. Exported profiles do not carry cached registration
evidence, so another gateway validates against its own selected issuer.

For a multi-output minter, declare each additional semantic output through the
profile's `additional_outputs`, targeting a sibling credential with exactly one
environment key and no independent refresh. The primary credential must also
have exactly one environment key. The primary output is the sole descriptor
output not mapped as an additional output, regardless of descriptor ordering.
Zero or multiple remaining outputs, missing outputs, duplicate keys, and
conflicting grant ownership fail validation. A single-output strategy needs no
additional mapping. See
[profile output bindings](/how-it-works/providers/profiles#additional-outputs).

The gateway checks collisions for the complete fixed output bundle before
allocation. Configuration creates pending references without minting. Use
`RotateProviderCredential` or wait for issuer scheduling to publish the first
bundle. Reuse the request ID on retries to avoid creating another grant epoch.

Workload placeholders stay stable when the issuer publishes a new value version
within a grant. Reconfiguring refresh creates a new authorization epoch and
revokes the previous placeholder identity.

The optional `refresh_before_seconds` and `max_lifetime_seconds` material entries
are gateway scheduling controls, not minter inputs. Without profile defaults,
they default to 300 and 3,600 seconds. Omitting a control uses the matching
profile duration when present; an explicit integer zero selects the gateway
default. Integer controls range from 0 through 43,200. Profile durations preserve
fractional seconds. Minters cannot declare fields with the scheduling-control
names.

Refresh configuration in both hosting modes, for built-in and custom strategies, rejects
`expiration_time` before creating a grant. Omit it: the issuer derives each
published value's expiration from the mint result, not from the previous value.

## Delete refresh without deleting credentials

`provider refresh delete` stops the selected grant and preserves its latest
published output bundle as static credentials. The issuer transfers the existing
references without reading or copying credential values through the gateway.
Reference versions and original token expirations stay unchanged; stopping
refresh does not make expiring tokens permanent. All outputs become independently
replaceable or removable through normal provider updates. Deletion revokes the
refresh-managed workload handle; restart processes that still hold that handle
so they receive the static credential binding.

Deletion requires the issuer to advertise grant-detachment support. If the grant
has not published its first values, deletion fails without changing its
configuration. Rotate first to obtain values, or delete the provider if you do
not need its credentials.

The gateway journals the transfer before stopping refresh and completes static
publication atomically with cleanup ownership. If a call disconnects or its
response is lost, recovery resumes the same transfer rather than revoking the
preserved values. Conflicting provider mutations fail closed while that transfer
is in progress. Reuse a stable request ID for API retries and check refresh
status after an uncertain response.
